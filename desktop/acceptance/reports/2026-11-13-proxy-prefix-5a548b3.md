## 1. 用户问题与前置结论

用户报告 Common Crawl 全部索引页数/首页读取失败，且原因摘要只有“network/读取失败”。
用户代理配置细节未返回，本机也无系统代理（`netsh winhttp show proxy` = 直接访问；
HTTPS_PROXY/HTTP_PROXY 未设置）。因此**不能把缺少用户代理信息当作根因**；本轮在受控
环境复现代理链路并检查产品错误摘要与配置传播。

## 2. 受控 HTTPS/CDX 链路（真实 Electron session）

脚本：`acceptance/proxy/run-https-proxy-acceptance.ts`（HTTPS 本地源站 + HTTP CONNECT
代理 + 认证代理 + HTTPS TLS 代理 + SOCKS5；生产 `createElectronSessions`/`net.request`、
生产 CommonCrawlAdapter/fetchText；活动环回使用测试专用 `<-loopback>` bypass 与测试
证书信任，脚本内明确标注，不冒充生产配置）。

修复前结果：

| 用例 | 结果 | 实测 |
|---|---|---|
| HTTPS CONNECT 免认证 | PASS | 200、collinfo 1 条、proxyHits=1 |
| HTTPS CONNECT HTTP 认证 | PASS | authorized=1、200 |
| HTTPS TLS 代理（代理本身 https） | PASS | 200、proxyHits=1 |
| SOCKS5 免认证 | PASS | 200、socksHits=1 |
| 代理连接拒绝 | PASS | `ERR_PROXY_CONNECTION_FAILED`，originDelta=0（不直连） |
| TLS 不受信 | PASS（可诊断） | `ERR_CERT_AUTHORITY_INVALID` |
| 429 / 503 | PASS（消息含状态） | `HTTP 429` / `HTTP 503`（但 AppError code 仍为 NETWORK） |
| 超时 | PASS | `TIMEOUT` |
| gzip | PASS | 解压后可解析，215 字符 |
| 大响应/字节预算 | PASS | `PARSE`，context.limit=100 |
| 取消 | PASS | `CLOSED` 请求已取消 |
| **错误代理认证** | **FAIL** | 仅 `ERR_TOO_MANY_RETRIES`，没有 407/auth 阶段 |
| **DNS 失败** | **FAIL** | 仅 `ERR_EMPTY_RESPONSE`，未区分 DNS/resolve |
| **OS system 模式 + HTTPS_PROXY** | **GAP/待核对** | system 模式指 OS 代理，不是环境变量；本机 OS 代理为直接访问，不能判错 |
| **显式 direct + HTTPS_PROXY** | **PASS（契约）** | 显式直连忽略环境代理，已确认不是缺陷 |
| **环境建议/手动应用** | **待核对** | 是否从 HTTP(S)_PROXY 提议、是否要求用户确认，契约未定 |

结论：受控的 HTTPS CONNECT/TLS 代理/SOCKS5 本身工作；无法在无用户代理信息的情况下
复现“所有 CC 索引读取失败”的同一根因。配置传播的契约已按总控判定纠正：显式 direct
忽略环境代理不是缺陷；OS system 不能用环境变量判定；环境建议契约未定。错误分类与
R9 摘要缺口仍可复现。

## 3. 错误摘要（生产 JobManager，R9）

新增 `acceptance/tests/r9-proxy-error-diagnostics.test.ts`，用生产 JobManager/适配器/
`fetchText` 重放相同的错误来源：

```text
node acceptance/run-acceptance.mjs
tests 108 / pass 102 / fail 5 / skip 1
```

5 个失败均为**摘要隐藏底层错误**：

| 用例 | 实测（view.reasons） | 期望 |
|---|---|---|
| CC 页数 429 | `network:索引 CC-MAIN-TEST 页数查询失败` | 含 429/HTTP 状态 |
| CC 页数 503 | 同上，无 503 | 含 503 |
| 代理连接错误 | 同上，无 proxy/代理阶段 | 含代理阶段 |
| TLS 证书错误 | 同上，无 cert/TLS | 含 TLS/证书 |
| 超时 | 同上，无 timeout/超时 | 含超时 |

这正是用户看到的“摘要只有 network”的原因，已独立复现；不是“没有存档”。

## 5. 配置矩阵与判定纠正（补充）

完整矩阵见 `acceptance/proxy/CONFIG_MATRIX.md`；关键更正：

- **显式 `direct`**：忽略 `HTTP_PROXY/HTTPS_PROXY` 是已确认契约，`explicit-direct-ignores-env` 通过，不列为缺陷。
- **OS `system`**：指操作系统代理，不是环境变量；本机无 OS 代理，`os-system-proxy` 标记 `gap`，不能判错，也不能证明用户 OS 代理可用。
- **环境建议/手动应用**：契约未定（待核对）；不得用“未自动应用环境变量”断言产品失败。
- 受控 fixed HTTP/HTTPS/SOCKS5 代理已验证；测试环回使用 `<-loopback>` bypass，HTTPS 源站使用自签测试证书与 `setCertificateVerifyProc` 信任，均为测试专用条件，已在脚本和矩阵标注，不冒充生产配置。
- R9 摘要缺口断言未改；curl 经测试代理超时与产品成功的差异仍未定位在测试代理或请求层，作为未决对照项保留，不能据此签通过。
